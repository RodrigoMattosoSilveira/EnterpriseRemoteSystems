# Enterprise Remote Systems — Detailed Test Cases and Test Data

## Document Purpose

This document converts the **Enterprise Remote Systems Comprehensive Test Plan** into a test-case catalog that a professional Testing Software Engineer can execute, refine, and import into a test-management tool.

It includes **247 test cases** extracted from the plan, with test data, preconditions, execution steps, and expected results.

## Execution Conventions

- Use unique run suffixes for records: `{RUN_ID} = YYYYMMDD-HHMMSS-random`.
- Prefix generated data with `e2e-`, `manual-test-`, or `qa-` so records are easy to identify.
- Unless a case explicitly says otherwise, use tenant `default` and an authorized actor with the necessary role.
- For authorization negative cases, verify both the visible UI result and the API response/status where possible.
- For financial cases, independently calculate expected ledger/current-account totals and compare them to the UI/API output.
- For journey completion cases, always verify closed-state behavior, ledger entries, receipt obligations, and audit logs.
